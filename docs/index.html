Frequently asked questions

How long does GitHub keep repository traffic data?

GitHub keeps only the last 14 days of views and clones, and only the top 10 referrers and popular paths. Older days are discarded, so this dashboard stores a snapshot every day to keep a permanent history.

How often is the dashboard updated?

A scheduled GitHub Actions workflow runs once a day. GitHub can take 24-48 hours to finalise a day's numbers, so the most recent days may still increase.

Does it show private repositories?

No. Private repositories are never read, stored or published. Only public repositories appear here.

Why are clones much higher than views?

Clones include automated traffic such as CI systems, mirrors and crawlers, so they are a weaker signal of human interest than views. Views and unique visitors are the better indicators.

What are unique visitors and why are they not added up over months?

GitHub reports a deduplicated unique-visitor estimate for its 14-day window only. Adding daily uniques would count the same person repeatedly, so longer periods show views and clones, not summed uniques.

How is the repository score calculated?

score = views in 30 days + 0.5 x clones in 30 days + 2 x unique visitors (14 days) + 3 x stars + 4 x forks. The top 20% of public, non-fork, non-archived repositories are marked top and the bottom 20% low.

How are API rate limits avoided?

Repositories with recent views are fetched daily, others every 3 days and dormant ones weekly. Because GitHub returns a 14-day window on every call, no data is lost. Calls are sequential, and the run stops safely if the remaining hourly budget gets low.

Can I run this for my own GitHub account?

Yes. It is open source under the MIT license: fork github.com/musman550/github-traffic-analytics-dashboard, add a GH_PAT secret with the repo scope, enable GitHub Pages on the main branch /docs folder and run the workflow.

Who can change this dashboard?

Only the repository owner can change the code and data. The main branch is protected, forks cannot write to it, and the site runs under a strict content-security policy.
